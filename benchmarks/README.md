# Bot 锦标赛性能分析与优化

测量日期：2026-11-22。运行环境：Windows、Oracle Java 26.0.2，JVM 堆固定为 `-Xms512m -Xmx512m`。以下均为本机结果，吞吐量随负载和 JIT 预热波动。

## 瓶颈与修改

1. **观测序列化**：每个行动都为全部单位构造属性、状态和技能的 Map/List，内置搜索与随机 bot 实际只读取合法动作和引擎状态。新增 `Bot.requiresUnitObservations()`，内置 bot 使用精简观测；自定义 bot 和已有搜索/战术 bot 的自定义子类默认保留完整快照。录像仍保存完整观测。
2. **阵容选择的重复工作**：明确指定内置预设时，原实现仍复制整个预设目录并读取、解析 DLC 官方练习队文件。现在直接查找指定的内置预设，仅复制所选阵容；其他预设与默认轮换继续原有流程。
3. **搜索临时分配**：每个搜索克隆原先都会创建三组属性计算缓冲区。搜索 bot 现在拥有独立的 `SearchScratch`，在同一线程顺序执行模拟时复用；战斗状态、随机数、可变 buff 和 DoT 仍独立复制。默认克隆 API 继续使用独立缓冲区。
4. **全量排序与重复动作生成**：候选选择改为稳定的前 K 项插入，保留分数相同时的合法动作顺序；根节点直接使用观测中已有的合法动作。
5. **其他分配**：直接生成技能动作，避免目标分组的多层临时列表；动作哈希取消 varargs 数组与整数装箱，保持哈希值相同；随机选择取消两个筛选列表；buff 到期清理改为原地压缩。

## 基准结果

| 项目 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 锦标赛，单线程 | 523.6 局/秒 | 3,476.4 局/秒 | 6.64 倍 |
| 锦标赛，四线程 | 1,587.6 局/秒 | 11,277.2 局/秒 | 7.10 倍 |
| 固定种子的随机对局 | 885.7 局/秒 | 4,884.9 局/秒 | 5.52 倍 |
| 固定深度 2 搜索 | 3,150.0 次/秒 | 4,138.6 次/秒 | 1.31 倍 |
| 每次搜索分配 | 638,080 字节 | 426,352 字节 | 减少 33.2% |
| 每局随机对局分配 | 4,118,522 字节 | 376,649 字节 | 减少 90.9% |

锦标赛每组 2,000 局，阵容为 `random:meta_direct_kill` 与 `random:meta_stun_kill`，种子从 42 开始，最多 40 回合，不录制录像。平均回合数均为 16.06。单局基准固定 seed=42，并传入相同阵容；搜索采用深度 2、根宽 8、分支宽 4，预热后测量 10,000 次。搜索前后均为 93 节点、3 次置换表命中，完整基准校验值均为 `1101166985460`。

分配量来自 `ThreadMXBean.getThreadAllocatedBytes`，表示分配总量，不是峰值内存；仅用于当前线程执行的微基准。锦标赛吞吐包含任务创建、bot 初始化、战斗和结果聚合，不包含报告文件导出与录像写入。

时间预算模式下，搜索通常会继续用完预算。此时改进主要体现为更多搜索节点，不应将随机 bot 的吞吐倍数套用到搜索 bot 锦标赛。未修改搜索深度上限、分支宽度、采样数和战斗规则。

原始输出见 `baseline.txt`、`optimized.txt`。本工作区没有 Git 历史，复测基线是在 `.cache/perf-baseline` 中复原优化前热点实现、单独编译至 `.cache/perf-baseline-out`，通过独立 classpath 与相同基准程序对比；该缓存仅供本次对比。

## 验证与复现

在项目根目录执行：

```powershell
.\build.ps1
java -Xmx512m -cp 'java/out;java/out-test' com.circus.TournamentPerformanceTest
java -Xms512m -Xmx512m -cp 'java/out;java/out-test' com.circus.TournamentBenchmark
```

新增回归检查覆盖 60 局、5,624 个回合，验证合法动作及顺序与原目标分组逻辑一致、动作哈希和随机选择不变、克隆状态/事件/RNG 一致、共享计算缓冲区不改变父状态、前 K 候选顺序一致、完整/精简观测下固定深度搜索选择一致、自定义 bot 获得完整观测、录像模式不改变对局统计、预设副本相互隔离。此外，80 局串行与四线程锦标赛的排名和逐局统计一致。

完整 `CircusTestSuite` 前后均为 15 项通过、1 项失败。唯一失败是已有的 `FMOD WAVWRITER_NRT mixed music WAV` 音频导出检查，优化前热点实现下也可复现；战斗、搜索、锦标赛报告及 HTTP/WebSocket 检查均通过。输出见 `baseline-suite.txt`、`optimized-suite.txt` 与 `regression.txt`。
